# 音声認識の挙動と既知の問題

このドキュメントは、本アプリが使う Web Speech API の挙動、実際に観測された問題、実施した対策、およびアプリ側では解決できない理由の記録である。

## 前提：Web Speech API の仕様

- 文字起こしはブラウザ標準の Web Speech API（SpeechRecognition）を使う。認識処理は裏側ではブラウザ提供元のサーバーによるストリーミング処理であり、精度と挙動はブラウザ依存で、アプリ側では制御できない
- 仕様上、セッション長の公式な規定はない。参考値として、Apple のネイティブ音声認識フレームワークのドキュメントには「音声は約1分を上限として計画する」とある
- セッションは時間経過のほか、無音の検出、発話の区切り、ネットワークの瞬断などでも終了しうる

## 観測された問題

いずれも30秒強〜1分程度の長文テイクで観測された。短いテイクでは安定している。

1. **空認識**：セッションは正常に継続しているのに結果イベントが一度も返らず、認識文が空になる。診断サマリー上は「セッション開始1回・再起動0回・結果イベントなし・エラーコードなし」という形で残る
2. **後半欠落**：認識文が途中で途切れ、以降が全て未認識になる。58語の文で、28語目（文の境界）や21語目付近で途切れた事例を確認した。録音音声自体は完全であることを再生で確認済みであり、喪失は認識側で起きている
3. **全文重複**：同じテイクの認識文が、全文2回繰り返された形で返る事例を確認した

## 実施した対策

- セッション終了時の自動再開を保証した。全ての終了経路は「再開する」か「理由を画面に表示して止まる」かのどちらかに落ちる。再開上限（30回）到達時も理由を表示する
- エラーと診断は握り潰さず画面（「音声認識の状態」）に表示する。空認識時は診断サマリーを必ず残し、失敗ログを端末内に保存する
- 採点は、認識エンジンが返す代替候補にも照合し、最も目標文に近い候補を採用する

## 解決できない理由

以下の経路はアプリ側の制御範囲外であり、対策は軽減までで根絶はできない。

- 終了イベントもエラーも返さずに結果が止まる停止があり得る。再開のトリガ自体が発生しないため、検出できない
- 暫定結果（interim）が確定結果になる保証がなく、セッション終了時に未確定分が失われうる
- 結果インデックスの挙動がブラウザ実装に依存し、結果の再送や跳躍があり得る

また、部分的に欠落したテイクについては診断情報が残らない設計上の制約があり、個別の事例で上記のどれが起きたか特定できない場合がある。

## 結論と運用

- API の仕様に沿った実装としては完了と判断した。これ以上のアプリ側修正で得られる改善は限定的である
- 運用上の回避策：録音前にページをリロードすると、初回テイクの成功率が最も高い
- 構造的に解決するには、録音後の音声を一括で文字起こしする方式（外部の音声認識サービス）への移行が必要になる。ただしその方式では音声が端末の外に出て、APIキーと従量課金が必要になるため、採用していない
